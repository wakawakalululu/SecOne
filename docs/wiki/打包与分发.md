# 打包与分发

SecOne 的分发形态：源码（本仓库）、Nuitka standalone 主程序、便携 ZIP、Inno Setup 安装包、独立模型资源包。三种二进制形态均可独立核验 SHA256，`dist/SHA256SUMS` 共 141 条已逐条复核。

## 1. 主程序（Nuitka standalone）

```powershell
pip install nuitka ordered-set zstandard
powershell -ExecutionPolicy Bypass -File packaging\build_exe.ps1 -Clean
```

`--standalone` 生成 `dist\SecOne\`，把 `config/`、`assets/`、`models/model.json`、许可与说明文件复制到主程序旁边，并创建运行期目录。**模型权重与 llama.cpp 二进制不进主程序包**。

RC1 实际产物：`dist/SecOne/SecOne.exe`（32,806,912 字节，SHA256 `babfc00a…c5fb`），启动冒烟通过，EXE 元数据版本 1.0.0.0。

## 2. 便携 ZIP

```powershell
Compress-Archive -Path dist\SecOne -DestinationPath dist\packages\SecOne-1.0.0-rc1-portable-win64.zip -Force
```

RC1 实际产物：46,901,540 字节，SHA256 `afd838ec78b365f7ecfb0510c9fda045d1acda80fe88bf764bc66855cba83a74`，138 个程序文件。包内不含任务库与日志，首次启动才创建 `data\` 与 `logs\`。解压后直接运行 `SecOne.exe`，不依赖系统 Python，也不需要安装 VC++ Redistributable（运行库随包携带）。

## 3. 安装包（Inno Setup）

```powershell
iscc packaging\SecOne.iss   # 需先完成上一步，确保 dist\SecOne\ 存在
```

RC1 实际产物：`dist/installer/SecOne-1.0.0-rc1-setup.exe`（32,140,884 字节，SHA256 `49e380b7…46e09`），Inno Setup 6.7.4 编译。默认安装到 `%LOCALAPPDATA%\Programs\SecOne`（当前用户，无需管理员权限）；隔离目录静默安装验证 145 个文件落盘，安装后 EXE 与 `dist\SecOne\SecOne.exe` 字节一致；卸载后任务数据与日志目录保留。

可执行文件名统一为 `SecOne.exe`；如需改名，改 `packaging/build_exe.ps1` 的 `--output-filename` 与 `packaging/SecOne.iss` 的入口文件名即可，不影响内部模块。

## 4. 模型资源包

```powershell
.\.python\python.exe scripts\package_model.py `
  --gguf models\XuanmuSec-v2-Q6_K.gguf `
  --runtime-dir runtime `
  --license licenses\LICENSE-XuanmuSec.txt `
  --license licenses\LICENSE-LFM1.0.txt
```

脚本校验 GGUF 文件头、计算 SHA256、生成带 `model.json`、许可文件与 `SHA256SUMS.txt` 的模型包目录和 ZIP（62 条清单）。包内是 `models/`、可选 `runtime/`、`licenses/` 与 `INSTALL.txt`，解压后合并到 SecOne 安装目录即可。模型与服务组件体积较大（XuanmuSec-2.6B Q6_K 权重 2.07 GiB，`runtime/` 53 个文件约 40 MB），作为独立下载项分发。

RC1 实际产物：`SecOne-model-XuanmuSec-2.6B-Q6_K.zip`（2,246,914,836 字节，SHA256 `eb77aecd…8e87`）；发布方 NOTICE 补齐前仅限内部验收。

## 许可门禁

- `ALWAYS_BUNDLED_LICENSES`：`Apache-2.0.txt` 必须随包（`LICENSE-XuanmuSec.txt` 引用它），缺失即终止打包。
- `RUNTIME_LICENSES`：分发 llama.cpp 二进制时必须附带 `LICENSE-llama.cpp.txt`（MIT），仅在 `--runtime-dir` 时强制。
- 缺少 `LICENSE-XuanmuSec.txt` / `LICENSE-LFM1.0.txt` 时脚本默认拒绝打包；仅在确认条款不适用时才可 `--allow-missing-model-licenses`。

## 部署依赖静态审计

```powershell
.\.python\python.exe scripts\audit_bundle.py --bundle dist\SecOne
```

23 项静态检查（RC1 全部通过）：主程序与内嵌 `python312.dll`/`python3.dll`、Qt 平台插件 `qwindows.dll`、Qt 核心/GUI/Widgets DLL、VC++ 运行库随包、发布配置、四份许可文本、首次启动目录为空、模型权重不误入程序目录、`SecOne.exe` 与配置文件无开发机路径泄漏。

该审计是静态证据，**不能替代**干净机器上的真实启动、渲染与写盘验证——干净 Windows 离线验收当前仍为 BLOCKED（见 [测试与验证](测试与验证.md) 与 [FAQ与已知边界](FAQ与已知边界.md)）。

## CI/CD 与跨平台

仓库带两条 GitHub Actions 流水线：

| 工作流 | 触发 | 内容 |
| --- | --- | --- |
| `ci.yml` | push main / PR / 手动 | Windows / Linux / macOS 三平台矩阵运行全部测试（offscreen Qt，Linux 预装图形库） |
| `release.yml` | 推送 `v*` 标签 | 三平台构建 → SHA256SUMS → 自动附加到 GitHub Release；`rc/alpha/beta` 标签自动标记 Pre-release |

三平台构建形态：

| 平台 | 打包方式 | 产物 |
| --- | --- | --- |
| Windows | Nuitka standalone（`packaging/build_exe.ps1`） | `SecOne-<版本>-portable-win64.zip` |
| Linux | PyInstaller onedir（`packaging/build_unix.sh`） | `SecOne-<版本>-portable-linux-<架构>.tar.gz` |
| macOS | PyInstaller onedir（同上） | `SecOne-<版本>-portable-macos-<架构>.tar.gz` |

布局三平台一致：程序旁边放 `config/`、`assets/`、`licenses/`、`models/`（清单与候选列表）、`runtime/`（仅 README）与空运行目录；模型权重与 llama.cpp 二进制不入包。Linux/macOS 的 `llama-server` 需按上游发行页自备放入 `runtime/`（Linux 版或 macOS 版），在设置页选择后启动。程序核心无 Windows 专属依赖：目录打开走 Qt 标准接口，子进程启动带平台回退，App ID 设置有 `sys.platform` 守卫。

手动补发产物：Actions 页对 `release.yml` 运行 `workflow_dispatch` 并填入已有 tag（如 `v1.0.0-rc1`），产物会覆盖附加到该 Release。
